## Selected engineering projects

### [sf-tui](https://github.com/0xguy07/sf-tui)

A keyboard-driven Salesforce terminal workbench built with **Go, Bubble Tea, and Lip Gloss**. It brings SOQL autocomplete, anonymous Apex, debug logs, test execution, permission exploration, and schema comparison into one interface on top of the Salesforce CLI. Distributed through Homebrew, Scoop, and release binaries.

### [sf-claude-studio](https://github.com/0xguy07/sf-claude-studio)

A **Claude Code harness for Salesforce delivery**: specialized agent roles, reusable skills, hooks, and path-scoped guidance across development, integration, testing, security, and deployment. An exploration of how to turn recurring engineering practices into reusable tooling and instructions.

### [timberborn-tools](https://github.com/0xguy07/timberborn-tools)

**Python tooling, reverse engineering, and MCP** for the city-builder Timberborn. Includes map generation and validation, documentation of the `.timber` save format, and a read-only MCP server for exploring colony saves. Game curiosity became an exercise in understanding unfamiliar systems and exposing them through useful tools.

### [DM Toolkit](https://github.com/0xguy07/dm_toolkit) & [companion extension](https://github.com/0xguy07/dm_toolkit_extension)

Tools for running **Dungeons & Dragons in Roll20**, pairing a Roll20 API script with a browser-extension interface. A practical way to explore browser APIs, integration, and the small workflow improvements that make a game session easier to run.

Across work and personal projects, I care about:

- **Root causes:** gathering enough evidence to explain why something broke.
- **Useful tools:** removing repetitive steps from an actual workflow.
- **Verification:** checking the result against the requirement, including what remains unknown.
